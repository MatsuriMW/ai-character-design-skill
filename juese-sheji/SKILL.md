# 角色设计

角色设计 = 先定**这是谁**（原型、性格、处境、弧光），再定**观众看见什么**（服化道、姿态、光）。

服化道不是给角色「穿上衣服」，而是**角色设计的一部分**：观众在角色开口之前，就已经从衣服、脸和手里的东西读出了这个人是谁、过得怎么样、在乎什么。一个好的造型满足三件事：

1. **真**：放在那个年代、那个城市、那个阶层里不穿帮。
2. **准**：能读出这个角色的性格、处境和变化。
3. **记得住**：观众散场后能用一句话说出「就是那个穿 X 的人」。

这个 skill 用这三条既做检验，也做发散，最后落到能生成的锁定段。

整个 skill 的底层是一条写法规则（`references/articulate-rules.md`）：**你能把要求说到多细，就能控制到多细；没说出来的维度，模型全部用默认值替你填。** 形容词是请模型猜，名词是给模型下单。所以人物最常见的起点（一个模糊的感觉）要先**具体化**；观众脑子里已有的原型，可以当具体化的初值。

## 先选模式

| 用户想要 | 模式 | 读 |
|---|---|---|
| 「轻佻的男性」「一个老年人」「有绅士感的人」「把这个人写具体」，手上只有一个模糊的感觉、一类人、一种风格、一段小传，或者一张原型卡，要变成能生成的精细描述 | **E 具体化** | `references/articulate-rules.md`、`references/styles/索引.md`、`references/dimensions/索引.md`（再按需打开风格库和各维度文件）、`templates/人物精细描述.md` |
| 「给我一个 XX 那种人」「这类角色一般长什么样」「来点人设灵感」「配角 / 群演怎么设计」，人物还没成形 | **D 人物原型** | `references/archetype-methods.md`、`references/archetypes/索引.md`、`templates/人物原型.md` |
| 「看看这身对不对」「检查一下」「有没有穿帮」「够不够出彩」，手上已经有造型（服化道表、角色卡、参考图、一段描述） | **A 检验** | `references/review-checklist.md`、`templates/检验报告.md` |
| 「这个角色穿什么好」「给点灵感」「头脑风暴」「还有什么别的可能」，造型还没定或者想推翻 | **B 创意风暴** | `references/brainstorm-methods.md`、`templates/创意风暴.md` |
| 「做服化道」「出服化道表」「道具清单」「连戏」，方向已经定了，要落成表和 prompt | **C 设计落地** | `references/design-principles.md`、`references/ai-lock.md`、`templates/服化道总表.md` |

五个模式可以连着用，最常见的顺序是 **E → B → C → A**：先把人具体化（需要灵感时先用 D 找原型当初值），想换造型方向时发散，再按场次落成表，最后自己审一遍。用户只要其中一个时，做完那一个就停，在结尾用一句话提下一步可以做什么。

**和其他 skill 的分工**（都是可选的，没有也能用：这个 skill 自己就交付能直接粘进生图 / 生视频的锁定段）：上游如果有分镜 / 导演类 skill，给节拍表和分镜；下游如果有角色设定板 skill（比如 `character-sheet`），直接用模式 E 的生图锁定段（或模式 C 的主造型 Look A）做设定板；按模型写 prompt 的 skill 用锁定段写镜头 prompt。

## 共同的第一步：收料

不管哪个模式，先读手上有的东西（有哪个读哪个；模式 D 只是要灵感、没有项目时可以跳过这一步）：
- 项目资料：剧本、人物小传、分镜稿、节拍表、规划（主题、色调、时代背景）。可能贴在对话里，也可能在项目目录里（默认约定见下面「产出存在哪」）
- 已有的角色卡、服化道、人物精细描述
- 用户给的参考图：打开看，提取款式、颜色（写成 HEX）、材质

**产出存在哪**：默认约定是一部短片一个目录 `shorts/<项目>/`，角色卡放 `character-sheets/<角色>/`。用户的工作区有自己的结构（或者在 CLAUDE.md / README 里写了约定）就按他的来；没有项目、只是要灵感时，直接在对话里给，不存文件。下文提到的 `shorts/<项目>/…` 都按这条理解。

然后确认四件事：**时代与地点、角色是谁（身份、性格、弧光）、整体色调、写实程度**。用户没说的**一次性**问完（有 AskUserQuestion 这类提问工具就用它，没有就在对话里一次列清楚，不要逐条追问）；说「你定」就从剧本推断，并在产出里标「推断」。

## 模式 E　具体化

目标：把一个模糊的感觉（「轻佻的男性」）拆成一个个维度，每个维度写成模型能直接执行的**名词或动作**，每一条都能单独替换、单独检查。规则全在 `references/articulate-rules.md`，开工前读一遍。

0. **定精细程度**：问一次（和收料的问题一起问）：
   - **一般**：只写〔全〕〔中〕可见的项。模型表现力一般（脸部细节会被吞掉）、或者只出全景 / 中景时用。
   - **深入**：〔特〕也写：皮肤纹理、痣、老茧、指甲、微表情。
   - 先查 `references/model-notes.md` 有没有这个模型的实测结果；没有就按用户说的模型推断，不确定选「一般」并说明。词库每一项都标了可见距离，也对应镜头景别。
1. **一句话定人**：把模糊感觉定义成「这是一个怎样的人」，1–2 行写身份、处境、他想要什么。剧本里没有的标「补」。
2. **查参考，再逐维度定写法**：先按 `references/styles/索引.md` 判断用户的说法属于哪一类，常常要叠着用：一个时代 / 圈子 / 制服 / 故事世界（民国、八十年代、机车党、空乘、武侠、赛博朋克）查 `references/styles/时代与类型.md`；一类人（老年人、教授、外卖骑手）查 `references/styles/人群与身份.md`；一种穿衣风格（绅士感、cityboy、老钱、知识分子气）查 `references/styles/服装风格.md`（47 个风格，从 Obsidian 风格库生成，可以换成自己的）；一种气质（轻佻、清冷、苦相）查 `references/dimensions/索引.md` 的「气质词 → 常用切口」。从参考里挑 5–8 条最能说明这个人的，不要整条照抄，在产出里写明参照了哪几条。再按需打开维度文件往下切。按 `templates/人物精细描述.md` 的维度总表，每个维度写一个**选定写法** + **2–3 个备选**，每个备选附一句「换成它会变成什么样」；每一行标清属于**身份 / 造型 / 状态**哪一层（`references/articulate-rules.md` 第 7 节：下一场换了衣服它还在不在）。选定写法要能放进同一个人身上不打架（轻佻 + 侧分油头 + 古巴领衬衫是一路；轻佻 + 寸头 + 冲锋衣就要说明为什么）。有原型卡就拿原型卡的服 / 妆发 / 道具 / 姿态当初值，再按「具体 + 反转」改。
3. **生活痕迹**：人物有职业、经历、习惯时，至少写 1–2 处经历留在手、脸、身体上的印子（`references/dimensions/06-生活痕迹.md`）。痕迹要和小传对得上。敏感痕迹按那份文件的「慎用」处理。
4. **不完美**：至少 2 处（可以和生活痕迹重合）。
5. **形容词残留检查**：把总表和四段里剩下的形容词圈出来（对照规则里的伞形词清单），逐个换成名词或动作；换不出来的列给用户，说明哪里需要他自己来定。
6. **拆成四段可粘贴**：① 生图锁定段（英文 + 中文对照，只写看得见的，不设字数上限；主设定写〔全〕〔中〕，身份层在前、造型层在后，深入档另加一段只在特写镜头用的「特写细节」；状态层不进锁定段，写进具体镜头）② 视频动作段（1–2 个习惯动作 + 1 处微表情，肌肉动作 + 幅度 + 时长）③ 表演说明（中文）④ 说话方式参考（语速、语调、音色、称呼、口头禅、句式 + 3 句示例台词；只作文字参考，不写进生成 prompt）。
7. 有项目存到 `shorts/<项目>/人物精细描述-<角色>-v<N>.md`；只要灵感、没有项目时直接在聊天里给，不存文件。示例见 `examples/轻佻的男性.md`。

用户只想换其中一项（「发型换成备选②」）时，只改那一行和受影响的段落，版本号加一。

**多个主要角色（群像）**：两个以上主要角色同场、或同属一部片的主角组时，每人做完模式 E 后，按 `references/ensemble.md` 填 `templates/群像对照表.md`：剪影、主色、发型轮廓、标志性单品、材质、姿态、说话七个轴，任意两人至少 4 轴不同、剪影和主色必须不同；做远景测试（只看剪影和主色、转黑白还能分清）和视觉领地检查；再用一处共同点表达他们的关系。改动回写各人的精细描述。多人同框的 prompt 按位置一人一段写。

**出图之后**：用户拿回生成结果（图 / 视频）时，按 `references/drift-checklist.md` 逐项审，哪些写了的东西被模型改回了平均值，每一项怎么修（把那一行写得更具体、加参考图），同一模型反复漂的项记进 `references/model-notes.md`。

**评测**：用户想知道具体化到底有没有用、某个模型能保住哪一层细节时，按 `evals/README.md` 跑（`evals/cases.md` 里 5 个现成用例，A 形容词组 / B 主设定组 / C 深入组对比）。出图要花积分，用户明确说跑、说了用哪个模型才生成。

## 模式 D　人物原型

目标：从影视里的经典人物原型出发，快速给出「一眼能认出」的人，再把它变成**这个故事里独一份**的人。图鉴在 `references/archetypes/`，122 张卡，按家庭、校园、职场、犯罪、底层、动作、奇幻科幻恐怖、爱情、东亚与短剧、喜剧配角分类。

1. **定需求**：这个人在故事里的功能（主角 / 对手 / 导师 / 配角 / 群演）、类型片、观众该对他有什么感觉、年代地点。用户只给了一个模糊画面（「一个苦命人」）也够了，先往下走。
2. **找候选**：读 `references/archetypes/索引.md`，按「一句话」和「按用途找」挑 3–5 个候选，再打开对应分类文件读整张卡。用户点名的原型图鉴里没有的，按卡片格式现写一张，标「新增」。
3. **每个候选做成一张人物原型卡**（`templates/人物原型.md`）：
   - **原样**：这个原型在影视里的标准样子（剪影、服、妆发、道具、姿态、光）。
   - **本土化**：翻译到这个故事的年代、城市、阶层，逐件换掉单品。
   - **1 + 1 + 1**：原型 + 一处具体 + 一处反转（方法见 `references/archetype-methods.md`）。
   - 一条英文 prompt（全身单人、米白背景，可以直接拿去出概念图）。
4. **至少给一个叠加或逆行的方案**：两个原型合成一个人，或者让角色在弧光里从一个原型走到另一个，服化道跟着换。
5. **查慎用**：涉及种族、民族、性取向、残障、地域的原型，对照 `references/archetypes/11-慎用.md`，要用就重写。
6. **推荐一个**，说清楚为什么。用户选定后：要写成精细描述转模式 E（原型卡当初值）；要细化造型转模式 B 或 C；要角色设定板交给角色设定板 skill（没有就直接用模式 E 的锁定段去生图）。
7. 只要灵感、没有项目时，直接在聊天里给，不存文件；有项目时存到 `shorts/<项目>/人物原型-v<N>.md`。
8. 用户想往图鉴里加新原型（「把 XX 也记进去」），按卡片格式写进对应分类文件，编号接着往后排，再在 `索引.md` 里补一行。

## 模式 A　检验

目标：像服装指导审片一样，指出这套造型**哪里不真、哪里不准、哪里记不住**，每一条都给改法。

1. **列出被审对象**：逐个角色、逐套造型、逐个重点道具，写清你审的是哪个版本。审的是**已经生成出来的图 / 视频**时，先按 `references/drift-checklist.md` 逐项对照人物精细描述打 ✓ / ✗，身份层漂了最严重；再看下面六个维度。
2. **按六个维度审**（细则和打分标准见 `references/review-checklist.md`）：
   - **时代与环境**：款式、面料、品类、价格带在那个年份和城市是否存在、是否常见；气候和季节；场合；物件（手机、支付、交通、包装）有没有穿帮。
   - **身份与处境**：收入、职业、居住、通勤能不能从衣服读出来；有没有「广告感」（太新、太整齐、太贵）。
   - **性格与弧光**：衣服在替哪种性格说话；从第一场到最后一场，服化道有没有跟着角色变化；变化是不是剧情给的理由。
   - **记忆点**：有没有标志性单品、剪影辨识度、颜色锚点；能不能用一句话概括；和同场其他角色拉不拉得开。
   - **画面与可生成性**：和场景色调的关系、和全片母题的呼应；锁定段能不能让 AI 稳定复现（有没有形容词、漏掉的部位、可能乱生的 logo）。
   - **形容词残留**：造型描述和锁定段里还剩多少「帅气」「高级感」「轻佻」这类伞形词（清单见 `references/articulate-rules.md`）；每个都要指出能换成什么名词或动作。
   - **痕迹对不对得上**：生活痕迹、体态、皮肤和人物的职业、经历、阶层是否一致（健身教练有啤酒肚、常年户外却冷白皮、说是农民手却白净 = 穿帮）；该有痕迹的地方有没有（`references/dimensions/06-生活痕迹.md`）。
   - 顺带看**原型**：这个角色是不是只剩一个原型、没有具体和反转（主角要有，配角可以没有）；有没有踩到 `references/archetypes/11-慎用.md` 里的套路。
3. **时代考据要有依据**：不确定的就联网查（用当前环境里的搜索、网页读取工具，查老照片、新闻、电商存档），查到写出处；查不到标「需查证」，**不要凭印象下结论**。
4. **出报告**：用 `templates/检验报告.md`。每个维度 1–5 分 + 一句话结论；问题按严重度排（穿帮 > 读错角色 > 没记忆点 > 可生成性）；每个问题写证据和具体改法；**也要写出该保留的亮点**，不要只挑毛病。
5. **结论**三选一：通过 / 小改后通过 / 需要重新发散（转模式 B）。
6. 存到 `shorts/<项目>/服化道检验-v<N>.md`。用户同意改动后，把修改落进下一版服化道（模式 C），不要直接改旧版。

## 模式 B　创意风暴

目标：先放开想，给出**彼此真正不同**的几条路，再收回来选一条。不是把同一身衣服换三种颜色。

1. **写角色的造型命题**：一句话说出这个角色最需要被看见的东西（例：「一个拼命不被注意的人」「穿着体面在硬撑的人」）。后面所有方向都围绕这句话。
2. **发散 4–6 个方向**：每个方向用一种不同的创意方法起手（方法库见 `references/brainstorm-methods.md`：反差、物件叙事、时间痕迹、色彩隐喻、母题呼应、职业细节放大、不合身、时代符号、借来的衣服……）。每个方向写成一张方向卡：
   - 概念名 + 一句话
   - 主造型（只写关键几件）
   - **标志性单品**（观众会记住的那一个东西）
   - 配色（3–4 个 HEX）
   - 它说了角色什么 / 弧光里怎么变
   - 参考来源（年代照片、职业、电影的**方法**，不照搬具体角色）
   - 风险（时代穿帮？太抢戏？AI 难生成？）
3. **至少一个大胆方向**：故意和第一直觉反着来。保守方向也留一个，方便对比。
4. **配角与道具的点子**：顺手给 3–5 个「小而准」的点子，比如一个会随剧情变化的道具、一个配角身上的反差细节。
5. **收敛**：用模式 A 的三条标准（真、准、记得住）给每个方向快速打分，推荐一个（或者两个方向的组合），说清楚为什么。
6. 用 `templates/创意风暴.md`，存到 `shorts/<项目>/服化道创意-v<N>.md`。用户选定以后转模式 C 落地。

需要看图比较时，可以给每个方向写一条造型概念图 prompt（全身单人、米白背景、4:3），只有用户明确说「生成」才调生图工具。

## 模式 C　设计落地

目标：让一部 AI 短片里**人穿什么、脸什么样、手里拿什么、屋里摆什么**都有依据、前后连得上，并且能被生图模型稳定复现。

1. **拆场**：按场次过一遍剧本 / 分镜，每场记下在场角色、时间（第几天、几点）、地点、内外景、天气，以及剧情里明确提到或画面必须出现的服化道元素。标出**时间跳跃点**（隔夜、隔天、闪回、平行世界），服化道的变化几乎都发生在这里。
2. **群像**：多个主要角色时，先确认 `templates/群像对照表.md` 做过（没做就按 `references/ensemble.md` 补），每一场的 Look 都不能让两个人在剪影和主色上撞。
3. **人物造型逻辑**：每个主要角色先写身份、性格和状态、弧光三行，再设计。原则和词表见 `references/design-principles.md`，更细的维度词库见 `references/dimensions/`。已经有人物精细描述（模式 E）的角色，主造型 Look A 直接从它的维度总表和生图锁定段接过来，这里只管**随场次怎么变**：身份层原样不动，换的是造型层（Look B / C），状态层（伤、湿、脏、疲惫）写进连戏表并标清生效的场次。
4. **出四张表**（模板 `templates/服化道总表.md`）：
   1. **造型卡（Look）**：每个角色每套衣服一张，编号 `<角色缩写>-A/B/C`，逐件写款式、颜色 HEX、材质、版型、做旧程度和「它在说什么」，并标出**标志性单品**。
   2. **妆发卡**：按状态写（`妆1 正常`、`妆2 连续加班第 5 天`），胡子、黑眼圈、发型乱度写成可量化的描述。
   3. **道具卡**：重点道具（每个一张卡，写数量、尺寸、状态变化）、手持道具、陈设道具（按场景列「必须有 / 可选 / 不能有」）。
   4. **场次 × 角色总表 + 连戏表**：每场每个角色穿哪套、什么妆发、拿什么；连戏表列随时间变化的东西在每个时间点的样子。
5. **写锁定段**：每个 Look、妆发状态、重点道具各一段英文锁定段，中文对照放旁边。**写之前必读** `references/ai-lock.md`。只写看得见的物理事实，每段末尾加 `Keep this outfit identical in every shot.`。一个镜头的 prompt = 角色锁定 + 本场 Look + 本场妆发 + 出镜的重点道具 + 镜头描述。
6. **自检**：交付前用模式 A 的六个维度快速过一遍，把发现的问题写进「待确认」。
7. 存到 `shorts/<项目>/服化道-v<N>.md`，迭代用新版本号，不覆盖旧版。设定板 prompt 多的话另存 `shorts/<项目>/服化道/`。

## 交付

回复里只说结论，不把整份表贴进聊天：
- 具体化：一句话定人；每个维度的选定写法各一句（不贴整张表）；生活痕迹和不完美；换不出来的形容词；四段可粘贴里直接给出生图锁定段（代码块），其余三段在文件里。
- 人物原型：几个候选各一句话（原型 → 本土化后是谁）、推荐哪个、为什么。
- 检验：总分和结论、最严重的 3 个问题、最值得保留的亮点。
- 创意风暴：几个方向各一句话、推荐哪个、为什么。
- 设计落地：拆了几场、几个角色、几套 Look、几个重点道具，哪些是推断补的、需要用户拍板。

## 规矩

- **不发明剧情。** 服化道可以补细节（这是本职），但补的东西要标「补」，方便用户删。检验时发现剧情本身有问题，可以指出，但不替用户改剧情。
- **不换脸。** 角色卡已经锁定的长相、发型，不要因为服装好看去改；确实不合适，在检验报告里提出来。
- **不照搬。** 参考电影和设计师的**方法**，不复制具体角色的造型。原型是观众的共同记忆，可以借；某个演员在某部片里的整套造型，不能抄。
- **不出现真实品牌 logo 和可读文字**，除非剧情需要，需要时写清文字内容。
- **考据不确定就查，查不到就标。** 不凭印象说「那个年代肯定有 / 没有」。
